# QAF Cinema — verified temporal buckets before Azure GPU training

**Scope:** private CPU preprocessing, reproducible 8n+1 frame counts and hash evidence. No Azure resources, pretrained model download, GPU job, LoRA training or cinematographic-quality claim.

## Why the gate is necessary

The recovered corpus audit reported 10 pose-guide pairs at 24 fps and 544x960, but each pair has 186 to 192 frames. LTX-2.5 requires video lengths following 8n+1; 186 and 192 are not valid. This tool selects a contiguous 121-frame window (approximately 5.04 seconds at 24 fps) using the same start frame for target and pose guide. It does not deliberately pad the source with invented frames.

Technical readiness is distinct from training readiness. Of the 10 named exercise clips, 8 have research QAF 8D metadata, 2 do not. Even available 8D vectors do not prove selected-window pose coverage, stable identity or garment quality. Legal, independent splits and human visual approval remain required.

## Commands — in the Codespace where the private videos actually exist

Update the video repository to the branch containing this tool. Run against the PRIVATE pair directory generated by the previous Copilot session. If that transient session directory no longer exists, regenerate the pairs from authorized source and verified MediaPipe evidence; never infer success from previous logs.

Dry run without any new clips:

    python scripts/qaf_cinema_temporal_buckets.py \
      --spec /private/qaf-pairs/pilot-pairs.json \
      --private-root /private/qaf-pairs \
      --out-root /private/qaf-pairs-121

CPU render only after dry-run succeeds; destination must not exist:

    python scripts/qaf_cinema_temporal_buckets.py \
      --spec /private/qaf-pairs/pilot-pairs.json \
      --private-root /private/qaf-pairs \
      --out-root /private/qaf-pairs-121 \
      --bucket 121 --start-frame 0 --min-guide-coverage 0.60 --execute

Verify using the pre-existing LTX control adapter:

    python scripts/qaf_cinema_ltx_control_adapter.py \
      --spec /private/qaf-pairs-121/pilot-pairs.json \
      --private-root /private/qaf-pairs-121 \
      --out /private/qaf-pairs-121/validated-ltx-manifest.json

The adapter writes a private official dataset sidecar. Keep personal observations, outputs and media out of public GitHub.

## What the code verifies

- Both input hashes match the private source-pairs manifest.
- Full decoded frame counts, constant 24 fps, and matching target/reference dimensions.
- A real 121-frame contiguous temporal window with identical start frame in both videos.
- Width and height divisible by 32.
- Outputs are decoded again and verified for exact 121 frames, 24 fps and geometry.
- Decodes the rasterized pose guide after cropping and checks that at least 60% of the selected frames show measurable skeleton marks. A sparse/blank guide fails closed. This proxy measures guide activity, not anatomical correctness or motion quality.
- New hashes of generated videos feed the existing IC-LoRA adapter.
- No overwrite of existing output. Partial new output is deleted on failure.
- If source bytes change between plan and render, the run fails.

If the entire batch fails because a guide is blank or sparse, review the source observations and create a new private spec excluding the failing pair(s). Do not lower the activity threshold merely to pass the gate. Be aware that multiple videos can have false-positive raster activity while still showing wrong joints.

Not verified: subjective visual quality, full selected-window pose confidence, biomechanics, cloth physics, model/actor/garment rights, leakage-free train-val-test splits, sponsorship coverage, or readiness to train GPU. Training remains explicitly unapproved.
